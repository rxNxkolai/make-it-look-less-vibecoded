Install

wick ships as ESM with types in the package. It needs Node 18 or newer, or any browser that supports modules. There is no build step and no plugin.

npm install wick
pnpm add wick
yarn add wick
bun add wick

Without a bundler, import it from a CDN and skip the install:

<script type="module">
  import { signal, effect } from "https://esm.sh/wick@0.7.2";
</script>

Your first signal

  1. Hold a value

    A signal is a function you call to read. Calling it inside a computed or an effect records that you depend on it.

    import { signal } from "wick";

const count = signal(0);
count();          // 0

  2. Derive from it

    A computed caches its result. It re-runs when a dependency changes, and not otherwise.

    import { computed } from "wick";

const doubled = computed(() => count() * 2);
doubled();        // 0, runs the function
doubled();        // 0, cached

  3. Do something with it

    An effect runs once immediately, then again whenever one of its reads changes. Writes happen through .set().

    import { effect } from "wick";

effect(() => console.log(count(), doubled()));
// logs: 0 0

count.set(21);
// logs: 21 42

Core API

Six functions. Everything else in wick is built from them, including the graph above.

signal(value, options?) → Reader<T>

Holds a value. Reading it inside a computed or effect records the dependency. Writing it invalidates everything downstream.

NameTypeMeaning
valueTThe starting value. Held by reference, never cloned.
options.equals(a, b) => booleanComparison used to decide whether a write is a change. Defaults to Object.is. Pass false to notify on every write.
options.labelstringName used in dev warnings and in the graph above.
 
const name = signal("ada");

name();                          // "ada"    read and track
name.set("grace");               // "grace"  write and notify
name.set(v => v.toUpperCase());  // "GRACE"  updater form
name.peek();                     // "GRACE"  read without tracking

Watch for. Writing an object in place will not notify, because Object.is sees the same reference. Replace the object, or pass equals: false.

computed(fn, options?) → Reader<T>

Derives a value from other reactive reads. It is lazy: fn does not run until something reads the result, and it re-runs only when a dependency has actually changed value.

NameTypeMeaning
fn() => TPure derivation. Reads are tracked for as long as they happen on this run.
options.equals(a, b) => booleanStops propagation when the new result compares equal to the old one.
 
const items = signal([{ price: 4 }, { price: 6 }]);
const total = computed(() => items().reduce((n, i) => n + i.price, 0));

total();   // 10, runs the function
total();   // 10, cached

Watch for. Dependencies are collected per run. A branch that was not taken is not tracked, so a computed can depend on different signals from one run to the next.

effect(fn, options?) → () => void

Runs fn once immediately, then again whenever its reads change. This is where you touch the DOM, log, or call an API. It returns a dispose function.

NameTypeMeaning
fn() => voidSide effect. Register teardown inside it with onDispose.
options.labelstringName used in dev warnings.
returns() => voidStops re-running and fires every teardown registered inside.
 
const stop = effect(() => {
  document.title = unread() + " unread";
});

stop();   // stops re-running, fires teardown

Watch for. An effect that writes to a signal it also reads will loop. wick throws after 1000 flush passes and names the effect in the message.

batch(fn) → T

Groups writes so subscribers see one consistent update instead of one per write. Returns whatever fn returns. Nested batches flush with the outermost one.

import { batch } from "wick";

batch(() => {
  first.set("Ada");
  last.set("Lovelace");
});   // the effect runs once, not twice

Try it. The checkbox in the graph above turns this on and off against the live effect counter.

untrack(fn) → T

Reads a value without recording it as a dependency. Use it when a value is an input to the work but should not cause the work to run again.

effect(() => {
  send(payload(), untrack(() => sessionId()));
});
// re-runs when payload changes, never when sessionId does
onDispose(fn) → void

Registers a teardown on the effect that is currently running. It fires before the next re-run, and once more when the effect is disposed. Calling it outside an effect is a no-op and warns in dev builds.

effect(() => {
  const id = setInterval(tick, 1000);
  onDispose(() => clearInterval(id));
});

Patterns

wick has no router, no store and no component model. These are the four shapes people end up writing, so they are documented rather than shipped.

Async values

There is no resource() primitive. Write one in fifteen lines and you keep control of cancellation. The live flag is what stops a slow response from overwriting a fast one.

Idle. Nothing has been requested yet. 
function resource(source, fetcher) {
  const state = signal({ status: "idle" });

  effect(() => {
    const key = source();
    let live = true;
    onDispose(() => { live = false; });

    state.set({ status: "loading" });
    fetcher(key).then(
      data  => { if (live) state.set({ status: "ready", data }); },
      error => { if (live) state.set({ status: "failed", error }); }
    );
  });

  return state;
}

const user = resource(userId, id => fetch("/api/users/" + id).then(r => r.json()));

Lists and keys

One computed per row keeps the work proportional to what changed. A row-level equals stops a whole-array replacement from invalidating rows whose contents are unchanged.

const rows = signal([]);
const byId = computed(() => new Map(rows().map(r => [r.id, r])));

function row(id) {
  return computed(() => byId().get(id), {
    equals: (a, b) => a?.rev === b?.rev
  });
}

// Replacing the array re-runs byId once.
// Only the rows whose rev changed re-run their own computed.

DOM binding

An effect per binding is the whole rendering story. Each one returns its own dispose, so a view is a list of disposes.

function bindText(node, read) {
  return effect(() => { node.textContent = String(read()); });
}

function bindAttr(node, name, read) {
  return effect(() => {
    const v = read();
    if (v == null) node.removeAttribute(name);
    else node.setAttribute(name, v);
  });
}

const view = [
  bindText(document.querySelector("#total"), total),
  bindAttr(document.querySelector("#save"), "disabled", isClean)
];

function unmount() { view.forEach(stop => stop()); }

Cleanup and ownership

An effect owns the effects created inside it. Disposing the parent disposes the children, in reverse creation order, after the parent teardown has run.

const stop = effect(() => {
  const socket = new WebSocket(url());
  onDispose(() => socket.close());

  effect(() => socket.send(query()));   // child of the outer effect
});

stop();   // closes the socket and disposes the child

Watch for. A child effect created inside a parent is disposed and recreated on every parent re-run. If that is expensive, hoist it and give it its own lifetime.

Interop

wick holds no opinion about your view layer. Two adapters cover most of it.

React

useSyncExternalStore wants a subscribe function, which an effect already is. Skipping the first run keeps React from re-rendering during subscribe.

import { useCallback, useSyncExternalStore } from "react";
import { effect } from "wick";

export function useWick(read) {
  const subscribe = useCallback(cb => {
    let first = true;
    return effect(() => {
      read();
      if (first) { first = false; return; }
      cb();
    });
  }, [read]);

  return useSyncExternalStore(subscribe, read.peek, read.peek);
}

Vue

A shallowRef written from an effect, disposed with the surrounding scope.

import { onScopeDispose, shallowRef } from "vue";
import { effect } from "wick";

export function toRef(read) {
  const out = shallowRef(read.peek());
  const stop = effect(() => { out.value = read(); });
  onScopeDispose(stop);
  return out;
}

Upgrading from 0.6

0.7 renamed the whole surface once so it would not have to happen again. The codemod handles the first four rows: npx wick-codemod@0.7 .

0.60.7Note
const [get, set] = signal(0)const v = signal(0) One reader with .set, .peek. Destructured pairs are gone.
memo()computed()Same behaviour, plainer name.
createEffect()effect()The create prefix was dropped across the API.
onCleanup()onDispose()Matches the name of the function effect returns.

Before you start. 0.6.4 is the final 0.6 patch and stays on npm. Pin it if you are mid-migration.
