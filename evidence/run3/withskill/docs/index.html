    Five functions

    The whole surface. Everything is a plain function, there is no class, no proxy, and no compiler step.

    Imports from sinew
    NameSignatureBehaviour
    signal signal(value) → read

    Holds a writable value. Call the returned function to read it. Writing an Object.is-equal value does nothing at all, so a slider that lands on the same integer twice costs nothing the second time.
    computed computed(fn) → read

    Derives a value from other reads. Lazy: fn does not run until somebody reads the result, and does not run again until one of the values it read last time changes.

    Dependencies are collected fresh on every run, so a branch that stops being taken stops being watched.
    effect effect(fn) → dispose

    Runs fn once immediately, then again whenever anything it read changes. Returns a function that unsubscribes it. Effects run after a write has finished propagating, never during, so an effect cannot observe a half-updated graph.
    batch batch(fn) → result

    Holds effects until fn returns. Three writes inside one batch cost one effect run instead of three. The measured version of that claim is two sections down.
    untrack untrack(fn) → result

    Reads inside fn without subscribing to anything. Use it when a computed needs to look at a value but should not re-run when it changes.

    What comes back

    signal and computed both return a function you call to read. Three properties hang off it.

    PropertyOnBehaviour
    .set(next)signal

    Writes, propagates, and flushes any effects that were waiting. Returns the value you passed.

    .peek()both

    Reads the current value without linking the caller to it.

    .nodeboth

    The internal record, with its deps and subs sets. Meant for tooling, and used honestly: the diagram at the top of this page reads node.deps on every tick to decide which wires are solid.

    Install

    npm install sinew

    Ships as ES modules. No build step, no plugin, no runtime dependency. Or skip the install and pull it straight into a page:

    <script type="module">
  import { signal, computed, effect } from "https://esm.sh/sinew";
</script>

    Your first eight lines

    import { signal, computed, effect } from "sinew";

const dose  = signal(18);
const ratio = signal(16);
const water = computed(() => dose() * ratio());

effect(() => console.log(water() + " g of water"));

ratio.set(15);

    Prints 288 g of water, then 270 g of water. The effect ran twice because water changed twice, and not once more.

    Batching, measured

    A claim about batching is worth nothing without a count. Both buttons build a fresh three-source graph with one computed and one effect, reset the counters after the first run, then write to all three sources. The figures on the right are what the counters read afterwards.

    Without batch, each write settles on its own and the effect runs again every time. Inside batch, the writes propagate as they happen but effects are held until the function returns, so the effect sees one settled graph.
